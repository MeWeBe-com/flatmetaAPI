## 2026-11-06 - Batching User Lookups in UserFollowers Queries
**Learning:** In social endpoints like `GetFriends` and `GetAllFriendRequest`, relationships can be bidirectional across `user_id` and `follower_user_id`. Querying users inside loops introduces an O(N) database query bottleneck. Because `User` records require filtering inactive users (`status != 3`), batch loading unique user IDs with `User::whereIn('id', $ids)->where('status', '!=', '3')->get()->keyBy('id')` converts N+1 queries into 2 queries while retaining exact business logic and keying for O(1) in-memory lookups.
**Action:** When handling graph or relational pivot tables where relationships can point in both directions, extract the target entity IDs across both foreign key columns, run a single `whereIn` query with index support, and `keyBy('id')` for constant-time resolution in loops.
